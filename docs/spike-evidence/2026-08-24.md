## 3. 两类 IOPM Assertion

执行：

```text
$ Scripts/verify-assertions.sh
PASS system: visible while held, absent after release
pid=82395 kind=system active=true seconds=4
pid=82395 kind=system active=false released=true
PASS display: visible while held, absent after release
pid=82570 kind=display active=true seconds=4
pid=82570 kind=display active=false released=true
```

验证方法：探针持有断言时，用 `pmset -g assertions` 同时核对 owner PID、断言类型和名字；进程释放后再次回读，确认名字消失。两类断言分别运行，未混用。

组合验证：持有 system idle lease 时执行主动熄屏，系统断言仍可见，`pmset displaysleepnow` 退出码为 0；6 秒后 lease 正常释放。这证明实现上可以“系统保持清醒、显示器熄灭”。主动熄屏不是“等待空闲超时”，因此不能单独证明所有硬件上的 idle timer 行为。

AppModel → WakeLeaseEngine 真实链路验证：

```text
$ npx lovstudio app lumos dev -- --start-guard --show-menu
Lumos dev ready pid=73959 mode=menu-bar

$ pmset -g assertions
pid 73959(lumos-app): PreventUserIdleSystemSleep named:
"Lumos preset taskGuard - 60D5A965-9B55-4C36-8F5A-32B455E8ECEE"

$ # 结束 App 后再次回读
PASS named App lease released
```

这条链路使用实际保存的 Profile，由 AppModel 获取 engine receipt；进程结束后断言消失。
测试期间未请求合盖管理员授权，也未修改持久电源设置。

## 3.1 三个 Preset 的 D5 闭环

端到端测试直接驱动生产 `PresetSessionController` 与 `WakeLeaseEngine`，不是另写一套测试状态：

| Preset | Trigger | 持有 | Exit / Recover |
| --- | --- | --- | --- |
| Agent 模式 / 任务守护 | 有白名单且 0 个匹配目标时无 assertion；首个目标出现后进入 active。没有白名单时由用户手动开始 | `systemIdleSleep`；两个目标减为一个时继续持有 | 最后一个目标退出，receipt 释放，状态为 `targetsFinished`；手动会话由用户停止 |
| 保持亮屏 | 用户开始即 active | 仅 `displayIdleSleep` | 用户停止即释放；安全撤销时进入 suspended，恢复后创建新 receipt |
| 随时可达 | 用户开始即 active，不检查目标 | 仅 `systemIdleSleep` | 目标数为 0 仍持有；用户停止或安全边界才释放 |

底层真实 IOKit 断言仍由本文件第 3 节的外部 `pmset` 回读验证；D5 测试验证的是同一引擎之上的场景决策、引用与退出顺序。

## 4. App、PID 与子进程

```text
$ .build/debug/lumos-spike apps
runningApplications count = 165

$ Scripts/verify-process-tree.sh
process = zsh
descendant = sleep, parentPID = zsh PID
PASS process tree
```

真实链路为脚本生成的 `zsh -> sleep`，不是伪造固定 PID。`proc_bsdinfo` 同时记录进程启动时间，供正式实现识别 PID 复用。

当前 App 已监听 Workspace launch/terminate 事件并立即刷新，同时每 5 秒以 libproc 全量快照
校正。`ProcessObservationProvider` 首帧只建立基线，后续比较 PID + 启动时间并输出 started、
terminated、replaced；真实 `/bin/sleep` 启动/退出测试通过，人工构造的同 PID 不同启动时间
测试产生 replaced。

限制：`NSWorkspace` 的普通 launch/terminate notification 不覆盖所有后台与 `LSUIElement`
App，因此不能只靠通知。对其他用户或受保护系统进程，libproc 信息可能不完整，设置页会显示
“身份不可读取”，不会把缺失信息误判为 Finished。

## 5. Low Power Mode 与 Thermal State

```json
{
  "lowPowerModeEnabled": false,
  "thermalState": "nominal",
  "operatingSystemVersion": "Version 26.6 (Build 25G72)"
}
```

`ProcessInfo` 读取成功。SDK 头文件显示 Low Power Mode 读取从 macOS 12.0 可用，Thermal State 从 macOS 10.10.3 可用，并提供对应状态变化通知。

D4 统一安全探针实测：

```text
$ .build/debug/lumos-spike safety-state
severity = normal
detail = 电量、温度与网络状态正常
refreshInterval = 5
powerSource = acPower, batteryLevelPercent = 100
thermalState = nominal, lowPowerModeEnabled = false
network = satisfied, wifi:en0
```

测试通过自建 NotificationCenter 实际投递 Low Power 与 Thermal 通知，并验证 monitor 读取新值；
IOPowerSources 与 NWPath 在本机做真实回读。serious/critical 和低电量边界使用可控输入验证安全
动作，没有人为加热电脑或断开正在使用的网络。

完成 Release 构建后的第二次真机回读自然出现 `thermalState=fair`，状态机输出
`severity=efficient`、`refreshInterval=15`，且三个安全撤销动作均为 false。这证明 fair
输入会降低 Lumos 自身校正频率；它不等于已在真机制造或验证 serious/critical。

当前只读探针进一步回读：正在使用 AC Power，当前 `lowpowermode=0`；Battery Power 的
独立配置为 `lowpowermode=1`。因此实现按当前电源来源选择 `pmset -c` 或 `pmset -b`，
不使用会覆盖两套策略的 `-a`。

低电量模式切换权限探针仅对 AC 当前值 `0` 请求再次设置为 `0`，避免改变有效配置：

```text
before=0
exit_code=1
message='pmset' must be run as root...
after=0
```

结论：读取是 direct；用 `pmset` 修改是 permission，P0 不做。

## 7. 立即熄屏与亮度

立即熄屏：

```json
{
  "executable": "/usr/bin/pmset",
  "terminationStatus": 0,
  "standardOutput": "",
  "standardError": ""
}
```

屏幕实际熄灭，并在约 2 秒后由预先安排的 `caffeinate -u` 用户活动唤醒。未修改持久电源设置，无需管理员权限。

亮度：

```json
[
  {
    "brightness": 0.5,
    "ioResult": -536870201,
    "serviceClass": "AppleARMBacklight",
    "source": "IORegistry observation; not a supported setter"
  }
]
```

旧的公开 `IODisplayConnect` 枚举为空。当前内置 Liquid Retina XDR 只在 `AppleARMBacklight` 注册表节点暴露可读参数；对该 service 调用 `IODisplayGetFloatParameter` 返回 unsupported。没有执行私有写入。结论为 experimental，而不是 direct。

## 8. 未执行或不能从单机得出的结论

合盖能力只读核验：

```json
{
  "detail": "系统睡眠已关闭，但不是由本次 Lumos 会话开启。",
  "isAvailable": true,
  "isSleepDisabled": true,
  "ownership": "external"
}
```

`ioreg` 同时回读 `AppleClamshellCausesSleep=Yes`、`AppleClamshellState=No`、
`SleepDisabled=Yes`。非 root 执行 `pmset -a disablesleep 1` 输出
`'pmset' must be run as root...`。该状态在 Lumos 本次实现前已经存在，所以测试仅做读取，
没有由 Lumos 关闭或重新写入。

- 未做真实合盖：当前只有内置显示器，不满足 Apple 官方闭盖外接显示器条件；也不会为了测试写入私有电源参数。
- 未安装特权 Helper；本轮只读验证未实际切换 Low Power Mode、`womp` 或其他持久电源配置。
- 未等待整机 idle sleep timeout：本机当时还有其他 App 的系统断言，且 AC `sleep=0`；本次验证的是 Lumos 断言的创建、类型、owner 与释放生命周期。
- 未验证 M1/M2/M4/M5、外接显示器或 macOS 14/15；这些属于发布前矩阵，不应从 M3 Pro 单机外推。
