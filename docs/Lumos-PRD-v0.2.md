# Lumos 产品需求文档（PRD）

> **版本：** v0.2 · 产品模型重构稿  
> **产品形态：** macOS 菜单栏 App  
> **Bundle ID：** `ai.lovstudio.lumos`  
> **Slogan：** 为未完成的事情，留一盏灯。

## 1. 产品定义

Lumos 是一款面向长时间任务与 Agent 工作流的 macOS 低功耗防休眠工具。

它的核心目标不是判断一台 Mac “该不该休息”，而是在用户明确要求任务持续运行时，解决两个天然矛盾的目标：

1. **Mac 不能休眠**，否则本地任务、网络连接与远程控制会中断；
2. **Mac 应尽可能低功耗**，否则持续唤醒会快速消耗电池并产生不必要的热量。

因此，Lumos 的核心命题是：

> **在保证任务连续性的前提下，只保留必要的清醒，把功耗压到当前场景允许的最低水平。**

可以将其表达为一个约束优化问题：

```text
minimize   Energy(policy)
subject to TaskContinuity >= userRequirement
           Safety          >= systemBoundary
```

任务感知不是产品目的，而是降低功耗的一种关键手段：Lumos 只有知道用户关心的任务是否仍在工作，才能在任务结束后及时撤销防休眠，也才能在任务等待期间采用更节能的策略。

一句更面向用户的表达是：

> **不让任务睡着，也不让电脑白白醒着。**

## 2. 核心场景

### 场景 A：长任务完成前不休眠

用户正在运行 ChatGPT/Codex Agent、视频导出、构建、测试或下载任务。屏幕可以熄灭，但任务完成前系统不能休眠；任务结束后，应自动恢复原来的电源策略。

### 场景 B：手机需要随时连接 Mac

即使当前没有进程处于高负载，用户仍可能从手机连接 ChatGPT Remote。此时“保持可达”本身就是任务，不能只依赖进程是否活跃。

### 场景 C：电池与合盖移动

用户拔掉电源、合上屏幕并短距离移动，同时希望任务不中断。Lumos 应尽量熄屏、降低功耗并加强热保护，但必须明确提示：合盖、密闭环境和持续高负载存在无法由软件消除的物理边界。

### 场景 D：只需要屏幕保持亮起

用户正在演示、阅读或查看监控面板，只需要防止息屏，不需要改变其他休眠与性能策略。

## 3. 产品模型：信号、原子控制与 Preset

Lumos 采用三层模型，而不是提供几个互斥的“大模式”。

```text
工作信号 Signals
      ↓
场景策略 Preset
      ↓
原子控制 Controls
      ↓
macOS 电源、显示、网络与性能状态
```

### 3.1 信号层：现在还有什么在工作？

用户可以建立一份“我关心的 App 与进程”列表。Lumos 持续观察这些对象，并判断它们是未运行、已运行还是正在工作。

需要区分：

- **Running：** App 或进程仍然存在；
- **Working：** 它正在执行用户希望保护的任务；
- **Waiting：** 任务仍未结束，但当前处于等待网络、模型回复或用户批准的低活动状态；
- **Finished：** 任务已经结束，可以撤销对应保护。

每个关注对象可以选择不同的 Working 判定规则：

| 判定规则 | 适用场景 | 可靠性 |
| --- | --- | --- |
| App 正在运行 | 普通应用 | 低：App 存活不等于任务存在 |
| 指定 PID/进程存在 | CLI、编码器、构建命令 | 中高 |
| 子进程或命令存在 | Agent 工具、构建链 | 中高 |
| CPU/I/O/网络超过阈值 | 无公开任务接口的应用 | 中：只能作为活动信号 |
| App 集成主动上报 | ChatGPT、Screen Studio、第三方工具 | 高 |
| 用户手动声明 | 无法自动识别的任务 | 由用户控制 |

Lumos 必须明确展示当前采用哪种判定规则，不能把“检测到进程存在”包装成“已理解任务状态”。

### 3.2 原子控制层：分别控制每一种系统行为

用户可以直接组合原子控制。Preset 本质上也是这些开关与参数的集合。

#### 显示

- 防止显示器因空闲自动熄灭；
- 允许显示器按系统设置熄灭；
- 立即熄屏；
- 设置内置显示器目标亮度；
- 电池供电时自动降低亮度。

#### 休眠

- 防止空闲系统休眠；
- 在最后一个关注任务结束后撤销防休眠；
- 高级合盖运行策略；
- 恢复 Lumos 启动前的系统状态。

#### 功耗

- 检测当前低电量模式；
- 请求切换低电量／自动能效模式；
- 任务 Waiting 时采用更保守的采样与后台活动；
- 限制 Lumos 自身轮询频率和资源占用。

#### 网络与可达

- 保持任务所需的网络会话；
- 检查“网络访问唤醒”的系统配置；
- 持续可达时，不依赖是否存在 Working 进程；
- 显示当前是“保持唤醒等待连接”还是“允许睡眠后网络唤醒”。

#### 安全边界

- 监测电源来源、电量与充电状态；
- 监测 macOS Thermal State；
- 设置低电量提醒与保护阈值；
- 严重热状态下撤销非关键控制并交还系统决策。

### 3.3 Preset 层：用场景组织原子控制

Preset 不是一个模糊的模式名称，而是一份可以查看、编辑与保存的策略：

```text
Preset = Trigger
       + Watched Targets
       + Working Rule
       + Atomic Controls
       + Exit Condition
       + Safety Boundary
```

用户一键启用 Preset，Lumos 展示它将修改哪些原子控制；高级用户可以展开调整，并保存为新的自定义 Preset。

## 4. 默认 Presets

### 4.1 任务守护

适用于 ChatGPT/Codex Agent、构建、测试、下载和普通后台任务。

| 项目 | 默认策略 |
| --- | --- |
| 触发条件 | 任一关注对象进入 Working 或 Waiting |
| 显示 | 允许熄屏，不阻止显示器休眠 |
| 系统 | 防止空闲系统休眠 |
| 功耗 | 电池时建议低电量模式 |
| 退出条件 | 所有关注任务 Finished 或用户手动停止 |
| 安全 | 低电量与 Thermal serious 时提醒并执行保护策略 |

### 4.2 随时可达

适用于手机随时连接 Mac、ChatGPT Remote 或远程终端。

| 项目 | 默认策略 |
| --- | --- |
| 触发条件 | 用户明确启用，不依赖 Working 进程 |
| 显示 | 允许或立即熄屏 |
| 系统 | 保持必要唤醒，或使用经验证的网络唤醒能力 |
| 功耗 | 优先低电量模式，降低 Lumos 自身活动 |
| 退出条件 | 用户关闭，或达到安全边界 |
| 安全 | 明确展示待机耗电；临界电量时优先停止持续可达 |

### 4.3 长时导出／渲染

适用于 Screen Studio、视频编码与持续高负载计算。

| 项目 | 默认策略 |
| --- | --- |
| 触发条件 | 指定导出进程或集成上报 Working |
| 显示 | 立即熄屏 |
| 系统 | 防止空闲系统休眠 |
| 功耗 | 默认自动能效模式，不强制低电量；由用户选择速度或续航 |
| 退出条件 | 导出完成、失败或进程退出 |
| 安全 | 强调通风；不推荐密闭书包；热状态升高时提醒或暂停 |

### 4.4 移动守护

适用于电池、合盖与短距离移动。

| 项目 | 默认策略 |
| --- | --- |
| 触发条件 | 用户主动启用，且至少一项关注任务未完成 |
| 显示 | 立即熄屏，亮度降至最低 |
| 系统 | 启用经验证的高级合盖策略 |
| 功耗 | 优先低电量模式，降低采样频率 |
| 退出条件 | 任务完成、开盖、接近低电量或热风险阈值 |
| 安全 | 最严格；持续高负载时明确建议取出电脑改善通风 |

### 4.5 保持亮屏

适用于演示、阅读、监控面板或临时展示。

| 项目 | 默认策略 |
| --- | --- |
| 触发条件 | 用户主动启用 |
| 显示 | 防止息屏 |
| 系统 | 由显示器断言自然防止空闲休眠，不增加其他控制 |
| 功耗 | 不自动切换性能模式 |
| 退出条件 | 用户停止或可选倒计时结束 |
| 安全 | 显示亮度与电池消耗提示 |

## 5. 菜单栏 UI/UX

### 5.1 指示灯的语义

菜单栏图标需要同时表达“任务状态”和“保护状态”，但不能只依赖颜色。

建议采用“灯芯＋光环”结构：

- **灯芯**代表关注对象是否 Working；
- **外部光环**代表 Lumos 是否正在执行防休眠或持续可达策略；
- **缺口／警示标记**代表电量、温度或能力降级。

| 状态 | 图标 | 含义 |
| --- | --- | --- |
| 无活动 | 空心灯芯、无光环 | 没有关心的任务在工作，Lumos 未干预系统 |
| 观察中 | 空心灯芯、细光环 | 已启用 Preset，等待关注对象开始工作 |
| Working | 实心灯芯、完整光环 | 关注任务正在工作，防休眠已生效 |
| Waiting | 半实心灯芯、完整光环 | 任务未结束但活动较低，继续保持必要唤醒 |
| 持续可达 | 无灯芯、完整光环 | 当前没有工作进程，但用户要求 Mac 随时可连接 |
| 风险／降级 | 图标增加缺口或警示点 | 电量、温度或系统能力限制了原策略 |

图标悬停或菜单首行必须给出自然语言，不让用户猜颜色：

> Screen Studio 正在导出，Lumos 已熄屏并防止系统休眠。

### 5.2 菜单展开结构

菜单栏主界面按决策优先级排列：

### A. 当前状态

- 一句话说明 Lumos 正在做什么；
- 电池、电源、热状态；
- 当前启用的 Preset；
- 一键停止保护。

### B. 正在关注

- 展示用户关注的 App/进程；
- 分别显示 Running、Working、Waiting、Finished；
- 支持添加当前运行的 App、选择进程或输入命令规则；
- 支持暂时忽略某个对象。

### C. Presets

- 一键切换默认 Preset；
- 展示每个 Preset 将改变的关键控制；
- 支持复制、编辑和保存自定义 Preset。

### D. 原子控制

默认折叠在“高级控制”中：

- 防止息屏；
- 防止系统休眠；
- 立即熄屏；
- 低电量模式；
- 亮度；
- 网络可达；
- 合盖策略；
- 电池和温度阈值。

任何原子控制被用户手动修改后，界面显示：

> 已从“任务守护”创建临时调整。

避免用户误以为原 Preset 已被永久修改。

### 5.3 可靠且温暖的文案

可靠感来自解释，温暖感来自不过度打扰。

- 无任务：`没有正在守护的任务。`
- 正在观察：`Lumos 在等它开始工作。`
- Working：`Lumos 正在为 Screen Studio 留灯。`
- Waiting：`Agent 正在等待回复，连接仍然保持。`
- 持续可达：`没有任务正在计算，但你的 Mac 仍可从手机找到。`
- 完成：`所有关注任务已经完成，Mac 恢复原来的休眠设置。`
- 热风险：`Mac 正在升温。建议取出电脑并改善通风。`
- 能力降级：`当前系统无法保证合盖后继续运行，开盖后会自动恢复守护。`

## 6. 能力与权限边界

不同原子控制的技术确定性不同，产品必须如实展示。

| 能力 | MVP 定位 | 说明 |
| --- | --- | --- |
| 读取前台与运行中 App | 直接支持 | 使用系统提供的 Workspace 能力 |
| 观察指定 PID/命令 | 直接支持 | 需要处理子进程与 PID 复用 |
| 防止显示器空闲熄灭 | 直接支持 | 使用显示器空闲休眠断言 |
| 防止系统空闲休眠 | 直接支持 | 电源断言是系统请求，不是绝对硬件命令 |
| 读取低电量模式 | 直接支持 | 可监听电源状态变化 |
| 读取 Thermal State | 直接支持 | 用于提示和策略降级 |
| 切换系统低电量模式 | 需验证／可能需权限 | 受 macOS 版本、机型和分发方式影响 |
| 调节内置屏幕亮度 | 需验证 | 外接显示器能力不一致 |
| 立即熄屏 | 需验证具体实现 | 不应模拟用户活动造成反向唤醒 |
| 网络访问唤醒 | 系统配置协同 | Apple 的能力主要面向共享资源，不等于任意 App 均可远程唤醒 |
| 电池合盖持续运行 | 实验性高级能力 | 必须建立机型与系统版本支持矩阵 |
| 降低第三方任务并发 | 仅集成后支持 | Lumos 不能无条件限制其他 App 的 CPU/GPU 使用 |

## 7. 安全与恢复原则

1. **用户明确授权：** Lumos 不在后台悄悄启用防休眠；
2. **原设置可恢复：** 修改前记录状态，Preset 结束或 App 异常后恢复；
3. **系统安全优先：** 低电量与热紧急状态可以覆盖用户 Preset；
4. **能力降级可见：** 某项控制未生效时明确说明，不显示虚假绿色状态；
5. **最小权限：** 只有确需修改系统配置时才安装特权 Helper；
6. **本地优先：** 关注对象、进程活动和策略历史默认仅保存在本机；
7. **不宣传物理不可能：** 不承诺密闭环境、高负载、低功耗和零发热同时成立。

## 9. 核心用户流程

### 9.1 创建任务守护

1. 用户在菜单中点击“添加关注对象”；
2. 从当前 App/进程中选择 ChatGPT、Screen Studio 或指定命令；
3. 选择 Working 判定规则；
4. Lumos 推荐“任务守护”Preset，并展示将启用的原子控制；
5. 用户确认后，Lumos 开始观察；
6. 对象进入 Working，指示灯灯芯亮起，防休眠生效；
7. 对象结束，灯芯熄灭；所有对象完成后撤销防休眠。

### 9.2 开启持续可达

1. 用户点击“随时可达”；
2. Lumos 说明即使没有 Working 进程也会持续耗电；
3. 用户确认后，外部光环亮起；
4. 菜单显示当前可达策略、电量与预计风险；
5. 用户关闭或达到安全阈值后，策略结束并恢复原设置。

### 9.3 自定义 Preset

1. 用户选择一个默认 Preset；
2. 展开“高级控制”；
3. 调整防止息屏、防止休眠、低电量、亮度和阈值；
4. 选择“仅本次使用”或“另存为新 Preset”；
5. Lumos 显示触发与退出条件摘要，用户确认保存。

## 10. 验收指标

### 连续性

- 支持场景中，因空闲休眠导致的任务中断率低于 1%；
- 多个关注对象并行时，不因单个对象结束而错误撤销保护；
- 最后一个任务结束至撤销防休眠的 P95 延迟低于 30 秒。

### 低功耗

- 无活动任务时，Lumos 自身平均 CPU 占用低于 0.5%；
- Waiting 状态使用事件驱动或低频采样，不维持高频轮询；
- 默认任务守护允许显示器按系统设置熄灭；
- 建立与裸 `caffeinate` 的同场景功耗基线，正式发布前确定节能目标；
- UI 能说明当前哪些控制正在降低功耗，哪些任务仍在消耗资源。

### 可靠性

- 用户两次点击内可以知道：谁在工作、为什么不睡、何时结束；
- App 崩溃、强退与系统重启后不遗留不可解释的电源设置；
- 原子控制实际未生效时，界面不得显示为成功；
- 所有风险和降级状态均同时使用图形与文字表达。

## 11. 待验证问题

1. 如何对 ChatGPT/Codex 的 Working、Waiting 与 Finished 建立稳定判定？
2. CPU、I/O 和网络活动阈值是否应由 App 模板提供，而非用户自行配置？
3. 低电量模式切换能否在不引入过高权限的前提下稳定实现？
4. 内置屏幕、不同外接显示器与不同 Mac 型号的亮度能力如何统一？
5. “随时可达”应保持整机唤醒，还是优先利用经验证的网络唤醒能力？
6. 电池合盖运行在哪些机型和 macOS 版本上可以可靠支持？
7. 如何测量各 Preset 相对裸 `caffeinate` 的真实节能收益？
8. 菜单栏单个图标是否足以表达任务、保护与风险三类状态？

## 12. 产品原则

Lumos 的价值不是提供更多电源开关，而是把这些开关组织成用户可以理解、信任并随时收回的场景策略。

它应始终遵守三句话：

> **任务没做完，就别让它意外睡着。**  
> **不需要的部分，就不要继续耗电。**  
> **环境不再安全，就诚实地停下来。**

## 13. 技术依据

- [Apple IOPM Assertion Types](https://developer.apple.com/documentation/iokit/iopmlib_h/iopmassertiontypes)：显示器与系统空闲休眠断言，以及低电量或热紧急状态下系统仍可覆盖断言。
- [Apple ProcessInfo](https://developer.apple.com/documentation/foundation/processinfo)：低电量模式、Thermal State 与状态变化通知。
- [Apple NSWorkspace.runningApplications](https://developer.apple.com/documentation/appkit/nsworkspace/runningapplications)：运行中 App 列表及其事件观察能力。
- [Apple：Mac 电源模式](https://support.apple.com/en-us/101613)：低电量、自动与高功率模式的系统行为和机型差异。
- [Apple：Mac 电池设置](https://support.apple.com/guide/mac-help/change-battery-settings-mchlfc3b7879/mac)：显示器、自动休眠、Power Nap 与网络访问唤醒的系统选项。
