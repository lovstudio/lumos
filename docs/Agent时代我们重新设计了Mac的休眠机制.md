# Agent 时代，我们重新设计了 Mac 的休眠机制

> 从 `caffeinate` 到任务感知：当人已经离开工位，电脑该如何知道自己还能不能休息？

过去，合上 MacBook 是一个非常确定的动作。

屏幕熄灭，网络安静下来，正在运转的世界被暂时封存在内存里。它像离开办公室前关掉最后一盏灯：人不再工作，电脑自然也应该休息。

但 Agent 改变了这件事。

现在，我们可能在 ChatGPT 里同时启动几个 Agent：一个重构代码，一个运行测试，一个整理文档；Screen Studio 还在后台导出一场数小时的课程录制；离开咖啡馆后，我们又希望在手机上查看进度、批准命令，甚至临时追加一条指令。

人已经走了，工作却还没有结束。

于是，一个过去近乎完美的交互——“合盖即休眠”——突然变成了阻碍。

大多数程序员遇到这件事，会经历一条相似的搜索路径：先翻系统设置，再读论坛和命令行教程，最后找到 macOS 自带的 `caffeinate`。它听上去正好：既然电脑想睡，就给它一杯咖啡。

```bash
caffeinate -i
```

命令运行之后，问题似乎解决了。直到我们把 Mac 合上，放进书包，坐进出租车；过一会儿再摸包，才发现机器依然在发热。更麻烦的是，`caffeinate` 只知道“不要因为空闲而睡”，却不知道谁还在工作、工作是否已经结束，也不知道电脑此刻是否适合继续工作。

这不是少了一个“禁止休眠”的开关，而是休眠机制所依赖的判断标准正在失效。

传统计算机默认，人离开，任务就结束；Agent 时代要求计算机理解另一种状态：**人可以不在场，但人的意图仍在持续执行。**

所以，我们重新思考了 Mac 的休眠机制。

---

## 第一个问题：什么时候计算仍然有价值？

计算机的休眠从来不只是一个技术细节，它是一套关于“什么时候计算仍然有价值”的判断。

早期计算机通常只有开机与关机两种直观状态。个人电脑，尤其是笔记本电脑普及后，电池成为稀缺资源，系统必须在性能、响应速度与续航之间选择。

1996 年 12 月 22 日，ACPI 1.0 规范发布。它把设备配置与电源管理的主导权进一步交给操作系统，使软件能够结合硬件和用户状态，在工作、空闲、睡眠与唤醒之间切换。[UEFI 保存的 ACPI 历史规范](https://uefi.org/acpi/specs)

![从大型机、ACPI 状态机到 Agent 时代的异步委托](generated_images/history-of-computational-value.png)

> **配图 01｜从“开或关”到“状态机”**：以 1996 年 ACPI 1.0 为中心，呈现大型机时代、个人电脑、笔记本电池与 Agent 时代四个节点。不要只放一张规范封面，而要让读者一眼看见：电源管理其实是一部“如何判断计算价值”的历史。

这套机制背后有一个长期有效、也极其合理的假设：

> 用户正在操作，意味着计算有价值；用户长时间没有操作，意味着计算可以暂停。

鼠标、键盘、屏幕和上盖，成为判断用户是否仍然“在场”的代理信号。因此，显示器长时间没有交互，可以熄灭；系统继续空闲，可以休眠；上盖被合上，则几乎可以直接推断：用户已经结束了这段工作。

macOS 至今仍保留这套逻辑。Apple 明确把“合上显示屏”列为让 Mac 笔记本进入睡眠的方式；而“不让显示器关闭后自动休眠”这一设置，在笔记本上面向的是接入电源的状态。Apple 也提醒，延迟或阻止休眠会增加耗电。[Apple：让 Mac 睡眠或唤醒](https://support.apple.com/guide/mac-help/put-your-mac-to-sleep-or-wake-it-mh10330/mac)；[Apple：设置睡眠与唤醒](https://support.apple.com/en-au/guide/mac-help/mchle41a6ccd/mac)

在传统桌面软件时代，这几乎没有问题。大多数任务都和人的操作同步：你点击导出，等待进度条；你按下运行，盯着终端；你关闭电脑，默认也接受任务暂停。

计算机的工作时间，基本等于人的在场时间。

但 Agent 把这两种时间拆开了。

## 第二个问题：当操作变成委托，电脑的工作时间由谁决定？

1960 年，J. C. R. Licklider 在《人机共生》中设想：人负责目标、假设与评价，机器承担其中可以程序化的工作。[《Man-Computer Symbiosis》](https://doi.org/10.1109/thfe2.1960.4503259)

![1960 年人机共生：人负责目标与判断，机器承担可程序化工作](generated_images/man-computer-symbiosis-1960.png)

> **配图 02｜1960，人机共生**：历史照片与概念插画结合。左侧是人在终端前操作机器，右侧是人把目标交给机器后离开；中间不是“AI 取代人”，而是一条从即时操作到异步委托的时间轴。

图形界面、个人电脑和互联网一点点实现了这个愿景，但很长时间里，我们使用计算机的基本方式仍然是“直接操作”。点击一个按钮，机器执行一个动作；拖动一个窗口，屏幕立即反馈。计算机主要是人手、眼睛和记忆的延伸。

Agent 带来的变化，不只是自然语言取代按钮，也不只是模型能够生成更多代码。更深层的变化是：**交互从操作变成了委托。**

当我们对 Agent 说“把项目重构完，运行测试，修复错误，再整理一份说明”，交出去的不是一个瞬时指令，而是一段需要在未来持续兑现的意图。

任务可能运行十分钟，也可能运行几个小时；它可能独立推进，也可能等待授权；一个 Agent 还可能派生多个子任务，同时调用终端、浏览器和文件系统。

这时，人的离开不再等于工作的结束。

OpenAI 对 Codex Remote 的描述非常直接：用户可以在手机上启动、指导、批准和审阅运行在已连接电脑上的任务。[Codex Remote 官方文档](https://learn.chatgpt.com/docs/remote)

这让一个看似边缘的电源管理问题进入了 Agent 体验的主链路：

- Mac 睡着，手机就找不到它；
- 网络连接断开，远程任务无法继续被观察和指导；
- 合盖事件可能暂停本地工具、构建、测试和导出；
- 用户不知道任务是完成了、失败了，还是仅仅睡着了。

GUI 时代的计算机围绕“人机同步”设计；Agent 时代的计算机必须支持“人机异步”。

过去，系统询问的是：**用户还在操作吗？**

现在，它还需要询问：**用户委托的事情完成了吗？**

## 第三个问题：在移动场景里，Mac 应该保持什么状态？

这不是我们在会议室里人为设定的一组产品目标，而是今天的移动生活自然产生的约束。

你在咖啡馆里启动几个 Agent，准备去下一个地点。出租车已经到了，你拔掉电源，合上电脑，把它放进书包。路上没有插座，屏幕也没有继续亮着的必要；但代码仍在修改，测试仍在运行，手机还要随时连回这台 Mac。

于是，五个条件同时出现：

1. 使用电池；
2. 合盖移动；
3. 任务不中断；
4. 手机仍可连接；
5. 尽量低功耗、低发热。

> **配图 03｜从咖啡馆到出租车**：一台合盖 MacBook 从桌面进入书包，手机仍能看见 Agent 进度。画面同时标注“电池、合盖、网络、计算、温度”五个约束，避免把书包里的持续满载描绘成安全或理想状态。

这些条件中存在一个软件命令无法抹掉的物理事实：

> 持续计算需要能量，消耗的能量最终会以热的形式离开机器；密闭环境又削弱了散热。

因此，“持续高负载、接近零功耗、密闭书包、完全不发热”不可能同时成立。

但用户口中的“在线”，并不总等于 CPU 和 GPU 满载。Agent 可能在等待云端响应，Remote 可能只是维持可达性，编译和测试通常是脉冲负载。真正持续消耗算力的，更多是本地模型推理、长视频编码和大型构建。

所以问题不是“怎样让电脑永远不睡”，而是：

> 怎样判断它此刻还能不能休息，并且只为尚未完成的事情支付必要的能量？

这不是一个开关问题，而是一个调度问题。

## 第四个问题：为什么程序员最常用的 `caffeinate` 仍然不够？

`caffeinate` 是很多程序员经过反复搜索后找到的第一个可靠答案。它是 macOS 自带工具，简单、免费，而且对下载、构建和脚本非常有效：

```bash
caffeinate -i make
```

根据系统手册，`-i` 创建的是“阻止空闲休眠”的断言；它也可以绑定命令或 PID，在对应进程退出后释放。[`caffeinate` 系统手册](https://keith.github.io/xcode-man-pages/caffeinate.8.html)

这套设计继承了 Unix 世界一种优雅的思想：把系统行为绑定到进程生命周期。但 Agent 时代的问题恰恰是，**进程不再等于任务。**

ChatGPT 桌面进程可以一直存在，其中的 Agent 却早已完成；Screen Studio 可以一直开着，只有导出期间需要阻止休眠；Remote 当前没有流量，不等于用户五分钟后不需要连接。

而且，空闲休眠不等于合盖休眠。Apple 对电源断言的定义也很克制：断言是应用向操作系统表达需求，不是对硬件状态的绝对命令；在低电量或热紧急状态下，系统仍可能选择休眠。[Apple IOPM Assertion Types](https://developer.apple.com/documentation/iokit/iopmlib_h/iopmassertiontypes)

`caffeinate` 的局限，可以归纳为五句话：

- 它理解进程，不理解任务；
- 它主要处理空闲，不完整处理合盖；
- 它没有跨应用的统一状态；
- 它不知道“未来随时可连接”也是一种需求；
- 它不负责电量、温度、并发与异常恢复。

继续修改 `pmset` 的全局策略，的确可以更强硬，却也更像把系统总闸固定在“开”：它需要更高权限、影响范围更大、容易遗忘恢复，也没有清晰的任务归属。[`pmset` 系统手册](https://keith.github.io/xcode-man-pages/pmset.1.html)

`caffeinate` 不是错。它只是回答了“如何暂时阻止空闲休眠”，却没有回答 Agent 时代真正的问题：为什么保持唤醒、为谁保持、何时结束，以及何时必须向电量和温度让步。

## 第五个问题：真实需求会把方案推到哪一层？

需求不是一下子变复杂的。它会沿着真实生活，一层一层变得更苛刻。

> **主信息图｜六级场景模型**：横轴从“桌面、单任务、插电”走向“移动、多任务、电池”；纵向同时展示所需能力与主要风险。文章发布时建议将下面六层压缩成一张可保存的信息图。

### 第一层：屏幕可以灭，但电脑暂时不能睡

电脑留在桌面上下载文件、执行脚本或跑一次构建。任务有明确进程，生命周期容易判断。系统电源断言或 `caffeinate` 足够。

### 第二层：使用电池，合盖后继续一个已知任务

例如导出一场数小时的录屏，或者让一个本地 Agent 完成代码修改。此时不仅要处理空闲，还要处理合盖；显示器应真正关闭，系统应进入低功耗模式，只保留任务需要的计算与网络。

### 第三层：任务时长不可预估

Agent 的结束时间无法提前计算。固定 30 分钟、1 小时或 2 小时，只是用另一种猜测替代休眠策略：太短，任务被中断；太长，任务结束后机器仍在包里无意义耗电。

结束条件不应该是时间，而应该是任务本身。

### 第四层：多个异构任务同时运行

ChatGPT 里有多个 Agent，一个等待批准，一个运行测试；Screen Studio 同时编码；手机还保留 Remote 需求。它们没有统一 PID，也没有统一的“完成”定义。

休眠不能再由某一个进程决定，而应该由多个任务共同决定。

### 第五层：手机必须随时能够连接

在手机真正发起连接前，Mac 上可能没有活跃请求。系统无法通过“当前网络是否繁忙”判断五分钟后用户会不会打开手机。

因此，“随时可连接”本身就是一项由用户明确开启的长期任务。不能等连接发生后才阻止休眠——那时电脑已经睡着了。

### 第六层：电脑正在书包里移动

此时，问题进入物理世界。Apple 建议 MacBook 在稳定、通风良好的表面使用，不要遮盖通风位置。[Apple：在适宜温度下运行 Mac 笔记本](https://support.apple.com/en-us/102336)

软件不能创造散热空间，但可以少制造没有价值的热：降低并发、启用低电量策略、区分等待与计算、观察系统热状态，并在温度升高时逐级收缩任务。真正成熟的方案不是假装限制不存在，而是在限制到来之前做出更聪明的选择。

## 核心机制：让每个未完成任务持有一份“唤醒租约”

最终，我们采用了一个简单的抽象：**Lease，租约。**

“禁止休眠”是一条没有上下文的命令；“租约”则是一段有所有者、有理由、有开始也有结束的承诺。

- Agent 开始执行，创建一份 Agent 租约；
- Screen Studio 开始导出，创建一份渲染租约；
- 用户开启手机 Remote，创建一份“随时在线”租约；
- 构建、下载与本地服务，也可以拥有各自的租约。

```text
shouldStayAwake = activeLeases.count > 0
```

只要仍有一份租约，Mac 就保持任务所需的最低唤醒状态；最后一份租约释放后，系统恢复原来的电源策略。

> **配图 05｜唤醒租约模型**：多个任务从左侧取得租约，中间的协调器合并需求，右侧输出“保持可达、继续计算、允许熄屏、恢复休眠”四种系统行为；电池和温度从下方作为硬边界介入。

一份租约必须回答四个问题：

1. **谁在持有？**——Agent、视频导出、远程连接，还是用户本人；
2. **为什么醒着？**——计算、网络、等待批准，还是保持可达；
3. **何时释放？**——任务完成、失败、连接关闭，或用户主动结束；
4. **何时让步？**——低电量、严重热状态、系统关机，或明确的安全策略。

电源管理于是第一次拥有了任务语义。

## 设计对象变了：从机器状态到人的托付

这件事不只关乎电源管理，也关乎我们如何理解工具。

海德格尔对工具的讨论里，有一个很有启发性的观察：真正顺手的工具通常不会成为注意的对象。木匠工作时关注的是要完成的东西，不是锤子本身；只有当锤子损坏、缺失或妨碍行动时，它才从背景中突然显现。[Stanford Encyclopedia of Philosophy：Heidegger](https://plato.stanford.edu/archives/fall2013/entries/heidegger/)

Mac 的休眠机制过去也是这种透明的工具。它自然到让我们忘了，其中其实包含了一套对人的判断：不操作等于不工作，合盖等于可以暂停。

直到 Agent 在合盖后离线，这套判断才暴露出来。它不是坏了，而是在忠实执行旧时代的语义。

1991 年，Mark Weiser 在《The Computer for the 21st Century》中写下普适计算的愿景：最深刻的技术会融入日常生活的背景，而不是不断索取注意力。[Scientific American 原文](https://www.scientificamerican.com/article/the-computer-for-the-21st-century/)

Agent 正在把计算机推向另一种“退入背景”。过去，这意味着界面自然、设备轻盈、操作无感；今天，它还意味着人在离开屏幕后，任务仍沿着被委托的方向推进。

人的时间是间断的：会离开、休息、换乘和切换生活场景。Agent 的时间是连续的：会等待、重试、调用工具和派生任务。计算机必须在两者之间保存的，不只是窗口和内存，而是**一件尚未完成的托付。**

传统休眠机制管理机器的空闲；Agent 时代的休眠机制，需要照看人的未完成。

## 我们做了 Lumos：为未完成的事情，留一盏灯

于是，我们开始做一款叫 **Lumos** 的 Mac App。

这个名字不是在要求电脑永远保持清醒。恰恰相反：当人离开之后，Lumos 只为仍然有价值的计算留下一盏必要的灯；任务结束，它也应该让灯自然熄灭。

Lumos 是产品名；**Wake Lease，唤醒租约**，是它背后的技术机制。前者回答我们想给用户怎样的感受，后者回答系统如何准确知道自己还能不能休息。

无论最终叫什么，它都不应该只是 `caffeinate` 的图形界面，也不应该把“永不休眠”包装成一个危险的大按钮。我们的设计理念有五条：

### 1. 让用户知道：为什么还醒着

菜单栏不只显示“On”，而是显示谁持有租约、处于计算还是等待、合盖后会发生什么。基础设施可以退到背景，但不能失去可解释性。

### 2. 完成之后，替用户把灯关上

不依赖无法预估的倒计时。任务完成，租约释放；最后一份租约结束，Mac 恢复原有休眠策略。用户不需要记得回来收尾。

### 3. 把电池和温度当作边界，而不是报表

macOS 提供 `nominal`、`fair`、`serious` 与 `critical` 等热状态，并建议应用随热状态升高减少资源使用。[Apple `ProcessInfo` 文档](https://developer.apple.com/documentation/foundation/processinfo)

因此，温度不是一个放在角落里的数字，而是调度输入：从限制并发、减少后台 I/O，到提醒用户改善通风，再到严重状态下暂停可暂停任务并交还系统控制。

### 4. 允许用户作出明确选择

“完成后休眠”适合一次性长任务；“持续可达”适合手机 Remote；“仅本次合盖”适合临时移动。App 应说明代价，让用户选择，而不是替用户偷偷修改全局设置。

### 5. 像守夜人，而不是监工

它不催促人留在电脑前，也不要求人时刻关注电量和进度。它只在需要时守住未完成，在有风险时轻声提醒，事情做完后把机器交还给安静。

> **配图 06｜Lumos 产品界面组图**：菜单栏展开页显示“当前 3 份租约”；详情页解释 Agent、视频导出与远程可达各自的状态；合盖前给出一句自然语言预告：“合盖后屏幕将熄灭，2 项任务继续，预计功耗较高。”

> **配图 07｜Lumos 网站首屏**：主标题写“为未完成的事情，留一盏灯。”下方用一个从咖啡馆到家的连续场景，展示人离开屏幕之后任务仍被可靠照看。

当它工作正常时，用户不需要记住 `caffeinate` 的参数，不需要反复检查 `pmset`，也不需要离开咖啡馆后猜测 Agent 究竟还活着没有。

他只需要合上电脑，然后继续生活。

## 最后的问题：当人离开之后，技术应该替我们守住什么？

过去几十年，个人计算机一直在学习如何更快响应人。

从命令行到图形界面，从鼠标到触摸屏，从菜单到自然语言，我们不断缩短意图与结果之间的距离。

Agent 带来的变化却不只是“响应更快”。它第一次让大量个人计算跨越人的持续注意力：我们提出目标，然后离开；机器在另一个时间尺度上搜索、修改、验证和等待；我们再从手机上回来，继续指导它。

这改变的不只是工作流，也改变了人与工具之间的伦理边界。

好的自动化，不应该要求人为了机器的连续运行而保持连续在线。人可以去赶车、吃饭、陪家人，也可以在一天结束时真正合上屏幕。技术的意义不在于把人也变成永不休眠的 Agent，而在于替人承接那些仍需继续的部分。

因此，新的休眠机制不该让 Mac 永远醒着。恰恰相反，它应该让电脑更准确地休息：任务未完成时，不擅自中断；环境不适合时，不假装物理限制不存在；事情结束后，也不继续无意义地消耗电量。

![技术替人守住未完成，并在任务结束后把灯关上](generated_images/technology-guards-the-unfinished.png)

> **配图 08｜最后一盏灯**：人已经回到生活中，桌面与屏幕退到背景；一条微弱的光代表仍在兑现的任务，完成后自行熄灭。画面要温暖，不要把“永远在线”塑造成英雄主义。

机器真正需要理解的，也许不是“人还在不在”，而是“人托付给我的事情，还剩下什么”。

真正有温度的技术，不是让机器永远醒着。

而是在你离开时替你守住未完成，在事情结束后替你把灯关上。
